## はじめに

天鳳の牌譜(mjlog)は、麻雀AIを作るときに最初に当たるデータです。ところが、読み方は次のようにあちこちに散らばっています。

- タグの意味は書いてあっても、**牌ID・副露コード・和了の読み方をひとつながりで試せる記事が少ない**
- コードがPerlだったり、変換ツール前提だったりして、そのまま機械学習用のデータに使いにくい
- 読んだ結果が正しいかを確かめる方法が書かれていない

この記事では、標準ライブラリだけのPythonで、mjlogを **読む → 局を再生する → 打牌予測の学習サンプルにする** ところまでを通します。

- 対象読者: 麻雀AIを作りたい人、牌譜を解析したい人。Pythonが読めれば、麻雀AIの経験は要りません
- 最後に、全体で約120行のコードが手に入ります
- 動作確認: 天鳳2023年の4人打ち3,000試合(約3万局)を再生して、全局で手牌の整合性が取れることを確認しました(後述)

:::note info
この記事のコードと数値は、私の手元の天鳳2023年ログ(鳳凰卓、4人打ち・赤あり)で確かめたものです。他の年・他の卓・三麻では確かめていません。牌譜の入手方法は[Apricot-Sさんのまとめ](https://qiita.com/Apricot-S/items/19864b3395cce566c719)が詳しいので、そちらを参照してください(利用規約とサーバー負荷の注意もそこにあります)。
:::

## 1. mjlogは「gzipで圧縮した、平らなタグの列」

天鳳の牌譜(`.mjlog`)は、gzipで圧縮したXMLです。展開すると、タグが入れ子なしで並んだXMLになります。

```python
import gzip
xml_text = gzip.open("xxxx.mjlog", "rt", encoding="utf-8").read()
```

この記事では、すでに展開済みの `.xml` を使います。実ログの冒頭を、名前を伏せて見ます(`SHUFFLE` は牌山の乱数情報で、長いので省きました)。

```xml
<mjloggm ver="2.3">
<GO type="169" lobby="0"/>
<UN n0="…" n1="…" n2="…" n3="…" dan="17,16,16,16" rate="2198.98,2107.85,2085.07,2181.49" sx="M,M,M,M"/>
<TAIKYOKU oya="0"/>
<INIT seed="0,0,0,4,0,92" ten="250,250,250,250" oya="0" hai0="121,18,19,…" hai1="30,135,100,…" hai2="…" hai3="…"/>
<T106/><D113/><U46/><E119/><V133/><F133/><W60/><G118/>
<T66/><D2/><U56/><E135/> …
<N who="1" m="10794" /><E46/> …
<AGARI ba="0,0" hai="24,25,50,53,56,93,94,95,100,102,103" m="10794" machi="50" ten="30,1000,0" yaku="8,1" doraHai="92" who="1" fromWho="3" sc="250,0,250,10,250,0,250,-10" />
<INIT seed="1,0,0,0,4,97" …
```

読み方の原則は3つです。

1. **`INIT` が1局の始まり。** 次の `INIT` か終局まで、その局の出来事が時系列に並ぶ
2. **ツモ・打牌は、タグ名が「誰か」を表す。** `T106` なら「座席0がツモ、牌ID 106」
3. **数字は全部整数。** 牌も副露も点数も、意味はビットや規則で決まる

### タグの一覧

| タグ | 意味 | 主な属性・読み方 |
|---|---|---|
| `GO` | 卓の種類 | `type` はビットフラグ(2章) |
| `UN` | 対局者 | 名前(URLエンコード)、`dan`(段位)、`rate`、`sx`(性別) |
| `TAIKYOKU` | 対局開始 | `oya` は起家 |
| `INIT` | 局の開始 | 局・本場・供託・ドラ表示牌、持ち点、親、配牌 |
| `T` `U` `V` `W` | ツモ | 座席0〜3の順。数字は牌ID |
| `D` `E` `F` `G` | 打牌 | 同じく座席0〜3の順 |
| `N` | 副露 | `who`(鳴いた人)、`m`(面子コード) |
| `REACH` | リーチ | `step=1` が宣言、`step=2` が成立(点棒を払った) |
| `DORA` | 槓ドラ | `hai` は新しいドラ表示牌 |
| `AGARI` | 和了 | 手牌・役・点数・点数移動 |
| `RYUUKYOKU` | 流局 | 流局の種類、点数移動、聴牌者の手牌 |
| `BYE` / `UN`(再) | 回線落ち / 復帰 | 6章 |

## 2. 卓の種類(`GO type`)は8ビット

`type` は、次のビットの組み合わせです。

| ビット | 値 | 立っていたら |
|---:|---:|---|
| 0 | 1 | 対人戦(0ならCPU戦) |
| 1 | 2 | **赤なし**(0なら赤あり) |
| 2 | 4 | **喰いなし**(0なら喰いあり) |
| 3 | 8 | 東南戦(0なら東風戦) |
| 4 | 16 | 三麻 |
| 5 | 32 | 特上(128と両方で鳳凰) |
| 6 | 64 | 速卓 |
| 7 | 128 | 上級(32と両方で鳳凰) |

「赤なしのときにビットが立つ」ことに注意してください(ビットが立っていると機能が付く、と読みたくなる向きの逆です)。実ログでも、ビット1が0の対局に赤5(ID 16・52・88)が出ています。

上位卓のビット(32と128)は、両方立っていれば鳳凰卓です。片方だけの場合の対応と、ビット2(喰いなし)・ビット4(三麻)は、手元のログに該当がなく確かめていません。

手元の2023年ログ(3,000試合の抽出)では、`type` は2種類だけでした。東風戦と東南戦の区別は、局数(`seed` の先頭の値の最大)が、225で平均3.1、169で平均6.5だったことでも裏づけられます。

| `type` | 中身 | 割合 |
|---:|---|---:|
| 169(=1+8+32+128) | 対人・東南戦・赤あり・喰いあり・鳳凰卓 | 87% |
| 225(=1+32+64+128) | 対人・東風戦・赤あり・喰いあり・速卓・鳳凰卓 | 13% |

麻雀AIの学習用には、まず `type & 0x10 == 0`(三麻でない)と `type & 0x02 == 0`(赤あり)で絞ると、扱うルールを1つにできます。

## 3. 牌ID(0〜135)は「種類 × 4枚」

牌は0〜135の整数で表します。麻雀の牌は34種類が各4枚なので、136個です。

![牌IDの並び](https://raw.githubusercontent.com/ShotaYmzk/mahjong-ai-qiita-images/main/tenhou_tile_id.png)

(牌の画像は、パブリックドメイン(CC0)で公開されている [FluffyStuff/riichi-mahjong-tiles](https://github.com/FluffyStuff/riichi-mahjong-tiles) を使いました。白は無地の牌です。各色の5は、通常の5(左)と赤5(右)を並べています。)

- **種類 = `ID // 4`**(0〜33。萬子0〜8、筒子9〜17、索子18〜26、字牌27〜33)
- **同じ種類の何枚目か = `ID % 4`**
- **赤5 は、各色の5の「0枚目」**(ID 16、52、88)。赤あり設定のとき、この3枚だけが赤になる

だから、AIの入力にするときは、次の2つを分けて持つのが基本です。

- 34種類(赤を区別しない)でどの牌か
- 赤かどうか(ID 16、52、88か)

この記事のコードでは、牌を `1m`〜`9m`、`1p`〜`9p`、`1s`〜`9s`、`1z`〜`7z` と書き、赤5は `0m` `0p` `0s` と書きます。

```python
def tile_str(t):
    if t in RED:            # RED = {16: "0m", 52: "0p", 88: "0s"}
        return RED[t]
    k = t // 4
    return f"{k % 9 + 1}{'mpsz'[k // 9]}"
```

実ログの1局目、座席0の配牌は次のとおりです。

```
hai0 = 121,18,19,74,43,83,47,90,113,2,120,73,45
     → 4z 5m 5m 1s 2p 3s 3p 5s 2z 1m 4z 1s 3p
```

`18` と `19` はどちらも `5m`(種類 `18 // 4 = 4`)で、ID 16 が赤です。この2枚は赤ではない5萬です。

## 4. 座席は「起家基準」。親とは別に持つ

最初にはまるのがここです。

- タグ `T U V W` と `D E F G` の並びは、**座席0〜3(起家から東南西北の順)**
- `INIT` の `oya` は、**その局の親の座席**
- `who` 属性も、座席番号

つまり、局が進むと親が座席1、2、3と動きますが、タグの文字(`T` `U` ...)は変わりません。「自分から見て下家・対面・上家」や、自風を出したいときは、**自分で計算します。**

```python
def relative(who, me):        # me から見た who。0=自分 1=下家 2=対面 3=上家
    return (who - me) % 4

def jikaze(seat, oya):        # 自風。0=東 1=南 2=西 3=北
    return (seat - oya) % 4
```

`INIT` の `seed` は、6つの整数のカンマ区切りです。

| 位置 | 内容 | 例(1局目) | 例(2局目) |
|---:|---|---|---|
| 0 | 局番号(0=東1局、1=東2局、…4=南1局) | 0 | 1 |
| 1 | 本場 | 0 | 0 |
| 2 | 供託(リーチ棒の本数) | 0 | 0 |
| 3, 4 | サイコロ(0始まり) | 4, 0 | 0, 4 |
| 5 | 最初のドラ表示牌(牌ID) | 92 | 97 |

`ten` は4人の持ち点で、100点が1です(`250` = 25,000点)。

## 5. ツモと打牌: 「ツモ切り」は自分で判定する

ツモは `T U V W`、打牌は `D E F G` です。

```xml
<T106/><D113/>      座席0が106をツモ、113を切る(手出し)
<U46/><E119/>       座席1が46をツモ、119を切る
<T33/><D33/>        座席0が33をツモ、33を切る(ツモ切り)
```

天鳳のmjlogには、**ツモ切りかどうかを示す印がありません**(他の形式、たとえば電脳麻将では記号が付きます)。抽出した300試合で、小文字のタグ(`d` `e` `f` `g`)は見つかりませんでした。判定は簡単で、**直前のツモ牌のIDと、打牌のIDが同じ**ならツモ切りです。

```python
tsumogiri = (drawn[who] == discard_tile)
```

3,000試合の約144万回の打牌のうち、直前がツモだったのは136万回で、うちツモ切りは54万回(40%)でした。残りの8万回は、チー・ポン・カンの直後などで、直前にツモがない打牌です。

:::note warn
鳴いた直後(チー・ポン)の打牌には、直前のツモがありません。この打牌は「ツモ切りではない」扱いにします。また、カンの直後は、**嶺上牌を引く `T U V W` が普通のツモと同じ形で出ます。** 嶺上開花かどうかは、タグだけでは分からず、直前が槓だったかで判断します。
:::

## 6. 副露(`N`)は16ビットのコード

副露は、鳴いた人 `who` と、面子コード `m` で表されます。`m` の下位ビットが、副露の種類を決めます。

```xml
<N who="1" m="10794" />
```

### 種類の判定

下位から順に調べます。

| 条件 | 種類 |
|---|---|
| ビット2が立っている(`m & 4`) | チー |
| ビット3が立っている(`m & 8`) | ポン |
| ビット4が立っている(`m & 16`) | 加槓 |
| どれも立っていない | 大明槓または暗槓(下位2ビットが0なら暗槓) |

どの場合も、下位2ビット(`m & 3`)は **誰から鳴いたか** を表します。鳴いた人から見て、1=下家、2=対面、3=上家です。鳴かれた牌を切ったのは、座席 `(who + (m & 3)) % 4` になります。チーは必ず上家(3)です。

### 中身の読み方

| 種類 | 牌の取り出し方 |
|---|---|
| チー | `t = m >> 10`、`r = t % 3`(順子の中で鳴いた牌の位置)、`t //= 3`。`t` は「順子の先頭の牌」を、萬子0〜6、筒子7〜13、索子14〜20と数えた値(先頭の牌の種類は `(t // 7) * 9 + t % 7`)。各牌の何枚目かは、`(m >> 3) & 3`、`(m >> 5) & 3`、`(m >> 7) & 3` |
| ポン | `t = m >> 9`、`r = t % 3`(使った3枚のうち鳴いた牌の位置)、`t //= 3`(牌の種類)。4枚のうち使わなかった1枚が `(m >> 5) & 3` |
| 加槓 | `t = (m >> 9) // 3`(牌の種類)。足した牌が `(m >> 5) & 3` 枚目 |
| 大明槓・暗槓 | `kind = (m >> 8) // 4`。4枚すべて |

コードにすると次のとおりです。

```python
def decode_meld(m):
    frm = m & 3
    if m & 0x4:                                   # チー
        t = m >> 10; r = t % 3; t //= 3
        base = (t // 7) * 9 + t % 7
        ofs = [(m >> 3) & 3, (m >> 5) & 3, (m >> 7) & 3]
        tiles = [(base + i) * 4 + ofs[i] for i in range(3)]
        return "chi", tiles, frm, tiles[r]        # 最後は鳴いた牌
    ...
```

(全体は後の「全コード」にあります。)

### 実ログで確かめる

実ログの局から、鳴きを5つ読みます。

| `who` | `m` | 結果 | 誰から |
|---:|---:|---|---|
| 1 | 10794 | ポン `8m 8m 8m` | 対面(座席3) |
| 2 | 49225 | ポン `6z 6z 6z`(發) | 下家(座席3) |
| 0 | 15915 | ポン `2p 2p 2p` | 上家(座席3) |
| 0 | 15923 | 加槓 `2p 2p 2p 2p` | (最初のポンと同じ) |
| 2 | 14391 | チー `5m 6m 7m` | 上家(座席1) |

座席0が `2p` をポンしたあと、同じ局で加槓していることが、`m` の値から読めます(15915 → 15923)。

### 手牌から取り除く牌

チー・ポン・大明槓で鳴いた牌は、**直前に誰かが切った牌**です。再生するときは、`m` から取り出した牌のうち、**直前の打牌のID以外**を、鳴いた人の手牌から取り除きます。

## 7. リーチ・ドラ

```xml
<REACH who="1" step="1"/><E91/><REACH who="1" ten="250,250,250,240" step="2"/>
<T118/><DORA hai="50" /><D118/>
```

- リーチは2段階です。`step="1"` が宣言で、続く打牌が宣言牌です。`step="2"` で点棒が払われて、リーチが成立します。宣言牌にロンが入ると、`step="2"` は出ません(リーチ棒は払われない)。3,000試合では、宣言22,151回のうち `step="2"` が出なかった784回は、すべて宣言牌へのロンでした。
- `step="2"` の `ten` は、点棒を払った後の持ち点です。
- `DORA` は、槓のあとに新しいドラ表示牌が出るタグです(最初の表示牌は `INIT` の `seed[5]`)。

## 8. 和了(`AGARI`)と流局(`RYUUKYOKU`)

### 和了

実ログの `AGARI` を読みます。

```xml
<AGARI ba="0,0" hai="24,25,50,53,56,93,94,95,100,102,103" m="10794"
       machi="50" ten="30,1000,0" yaku="8,1" doraHai="92" who="1" fromWho="3"
       sc="250,0,250,10,250,0,250,-10" />
```

| 属性 | 意味 |
|---|---|
| `who` / `fromWho` | 和了した座席 / 放銃した座席。**同じならツモ和了** |
| `hai` | 和了時の手牌(副露を除く。和了牌を含む) |
| `m` | 副露の面子コード(複数あればカンマ区切り) |
| `machi` | 和了牌の牌ID |
| `ten` | `符, 点数, 満貫以上の区分`。区分は 0=なし、1=満貫、2=跳満、3=倍満、4=三倍満、5=役満 |
| `yaku` | `役ID, 翻, 役ID, 翻, …`(役満では `yakuman` に役IDだけ) |
| `doraHai` / `doraHaiUra` | ドラ表示牌 / 裏ドラ表示牌 |
| `sc` | `持ち点, 増減` を座席0〜3の順に並べたもの(100点単位) |
| `ba` | `本場, 供託` |

この例は、座席1が座席3から、断幺九1翻30符(1,000点)でロンしたものです。

役IDのうち、実ログの和了手と突き合わせて意味を確かめたものを挙げます。(全一覧は[kobalabさんの連載](https://blog.kobalab.net/entry/20170225/1488036549)を参照してください。)

| ID | 役 | ID | 役 |
|---:|---|---:|---|
| 0 | 門前清自摸和 | 28 | 対々和 |
| 1 | 立直 | 34 | 混一色 |
| 7 | 平和 | 35 | 清一色 |
| 8 | 断幺九 | 52 | ドラ |
| 18 / 19 / 20 | 白 / 發 / 中 | 54 | 赤ドラ |
| 22 | 七対子 | | |

確かめ方は、たとえば「役ID 7(平和)の和了は、副露が0であること」「役ID 54の翻数は、手牌と副露にある赤5の枚数に等しいこと」を、6,000試合の和了すべてで調べました。ここに挙げた役は、すべて矛盾がありませんでした。

### ダブロン

1つの局で、`AGARI` が **2回以上**出ることがあります(ダブロン)。3,000試合の抽出では、30,127局のうち162局(0.5%)でした。局ごとに和了を**リストで持つ**ようにしないと、2つ目を上書きしてしまいます。

### 流局

```xml
<RYUUKYOKU ba="0,1" sc="250,-10,260,-10,250,-10,230,30" hai3="3,5,40,…" />
```

- 荒牌平局では `type` がなく、`sc` の増減が、ノーテン罰符の移動を表します
- **聴牌していた人の手牌だけが `hai0`〜`hai3` に出ます**(上の例は座席3だけ)
- 途中流局と流し満貫には `type` が付きます。3,000試合では、`yao9`(九種九牌)、`kaze4`(四風連打)、`reach4`(四家立直)、`kan4`(四開槓)、`nm`(流し満貫)が出ました。流し満貫は荒牌平局の一種ですが、`type` が付く点に注意してください
- **流局の手牌には、副露した牌が含まれません**。副露は、再生中に自分で覚えておきます

### 終局(`owari`)

最後の局の `AGARI` か `RYUUKYOKU` に、`owari` 属性が付きます。

```
owari="-20,-52.0,512,61.2,376,17.6,132,-26.8"
```

座席0〜3の順に、**最終持ち点(100点単位)と、順位ポイント**の組です。この例では、持ち点が -2,000 / 51,200 / 37,600 / 13,200点で、合計は100,000点です。3,000試合すべてで、持ち点の合計は100,000点、ポイントの合計は0でした。最終順位は、持ち点の大きい順に決めます(同点の扱いは、この記事では確かめていません)。

## 9. はまりどころ

| 状況 | 起きること | 対策 |
|---|---|---|
| 回線落ち | `<BYE who="2" />` のあと、`<UN n2="…" />` が復帰として出る | `UN` は `dan` 付きの最初の1つだけを対局者情報として読む |
| ダブロン | `AGARI` が1局に複数 | 和了をリストで持つ |
| カン | カンの直後の `T U V W` が嶺上牌 | 直前が槓かを状態として持つ |
| 流局の手牌 | 副露が入らない | 副露は再生中に覚える |
| 赤なし・三麻 | 牌IDの意味が変わる、抜きドラのタグが出る | `GO type` で最初に弾く |
| 座席 | `T U V W` は起家基準、親は `INIT` の `oya` | 4章の計算を使う |
| ツモ切り | 印がない | 直前のツモ牌と同じIDか |
| 名前 | URLエンコードされている | `urllib.parse.unquote`。個人名なので、公開する図表には載せない |

## 10. 全コード

ここまでをまとめた、約120行のコードです。標準ライブラリだけで動きます。

```python
"""天鳳XML(mjlog)の最小パーサ。記事に載せる版。標準ライブラリだけ。"""
import re
import xml.etree.ElementTree as ET
from urllib.parse import unquote

SUITS = "mps"
RED = {16: "0m", 52: "0p", 88: "0s"}  # 赤5のID


def tile_str(t):
    """牌ID(0-135) -> 'm1'形式ではなく '1m' '5z' '0m'(赤5)"""
    if t in RED:
        return RED[t]
    k = t // 4
    return f"{k % 9 + 1}{'mpsz'[k // 9]}"


def parse_go(t):
    return {
        "対人": bool(t & 0x01), "赤なし": bool(t & 0x02), "喰いなし": bool(t & 0x04),
        "東南": bool(t & 0x08), "三麻": bool(t & 0x10), "上卓": bool(t & 0x20),
        "速": bool(t & 0x40), "上級": bool(t & 0x80),
    }


def decode_meld(m):
    """N タグの m を (種類, 牌ID のリスト, 誰から(0=自分,1=下家,2=対面,3=上家)) にする"""
    frm = m & 3
    if m & 0x4:  # チー
        t = m >> 10
        r = t % 3
        t //= 3
        base = (t // 7) * 9 + t % 7            # 牌種(0-26)
        ofs = [(m >> 3) & 3, (m >> 5) & 3, (m >> 7) & 3]
        tiles = [(base + i) * 4 + ofs[i] for i in range(3)]
        return "chi", tiles, frm, tiles[r]      # 最後は鳴いた牌
    if m & 0x8:  # ポン
        t = m >> 9
        r = t % 3
        t //= 3
        unused = (m >> 5) & 3
        tiles = [t * 4 + i for i in range(4) if i != unused]
        return "pon", tiles, frm, tiles[r]
    if m & 0x10:  # 加槓
        t = (m >> 9) // 3
        added = t * 4 + ((m >> 5) & 3)
        return "kakan", [t * 4 + i for i in range(4)], frm, added
    # 大明槓 / 暗槓
    kind = (m >> 8) // 4
    tiles = [kind * 4 + i for i in range(4)]
    return ("ankan" if frm == 0 else "daiminkan"), tiles, frm, None


def load(path):
    """1対局を {meta, rounds} にする。rounds[i] = {init, events, ends}"""
    root = ET.parse(path).getroot()
    meta, rounds, cur = {}, [], None
    for e in root:
        tag, at = e.tag, e.attrib
        if tag == "GO":
            meta["go"] = int(at["type"])
        elif tag == "UN" and "dan" in at:   # 回線落ちの再接続でもUNが出るが、dan付きは最初だけ
            meta["dan"] = [int(x) for x in at["dan"].split(",")]
            meta["rate"] = [float(x) for x in at["rate"].split(",")]
        elif tag == "INIT":
            cur = {"init": dict(at), "events": [], "ends": []}
            rounds.append(cur)
        elif cur is not None:
            m = re.fullmatch(r"([TUVWDEFG])(\d+)", tag)
            if m:
                cur["events"].append(("draw" if m[1] in "TUVW" else "discard",
                                      "TUVWDEFG".index(m[1]) % 4, int(m[2])))
            elif tag == "N":
                cur["events"].append(("meld", int(at["who"]), int(at["m"])))
            elif tag == "REACH":
                cur["events"].append(("reach", int(at["who"]), int(at["step"])))
            elif tag == "DORA":
                cur["events"].append(("dora", None, int(at["hai"])))
            elif tag in ("AGARI", "RYUUKYOKU"):
                cur["ends"].append((tag, dict(at)))   # ダブロンだと AGARI が2つ付く
    return meta, rounds


def replay(rd):
    """1局を再生し、「誰かが牌を切る直前」の状態を1件ずつ返す(= 打牌予測の学習サンプル)"""
    seed = [int(x) for x in rd["init"]["seed"].split(",")]
    hands = [[int(x) for x in rd["init"][f"hai{i}"].split(",")] for i in range(4)]
    rivers = [[] for _ in range(4)]        # [(牌ID, ツモ切りか)]
    melds = [[] for _ in range(4)]         # [(種類, 牌IDのリスト)]
    dora = [seed[5]]
    riichi = [False] * 4
    drawn = [None] * 4                     # 直前にツモった牌(鳴いた直後はNone)
    last = None                            # 直前の打牌 (who, 牌ID)
    for kind, who, v in rd["events"]:
        if kind == "draw":
            hands[who].append(v)
            drawn[who] = v
        elif kind == "discard":
            assert v in hands[who], "手牌にない牌を切っている"
            yield {"who": who, "hand": sorted(hands[who]), "drawn": drawn[who],
                   "melds": [list(m) for m in melds], "rivers": [list(r) for r in rivers],
                   "dora": list(dora), "riichi": list(riichi), "label": v}
            hands[who].remove(v)
            rivers[who].append((v, v == drawn[who]))
            drawn[who] = None
            last = (who, v)
        elif kind == "meld":
            typ, tiles, frm, called = decode_meld(v)
            if typ in ("chi", "pon", "daiminkan"):
                assert last and last[1] in tiles and last[0] == (who + frm) % 4
                for t in tiles:
                    if t != last[1]:
                        hands[who].remove(t)
            elif typ == "kakan":
                hands[who].remove(called)
                melds[who] = [m for m in melds[who] if not (m[0] == "pon" and m[1][0] // 4 == tiles[0] // 4)]
            else:  # ankan
                for t in tiles:
                    hands[who].remove(t)
            melds[who].append((typ, tiles))
        elif kind == "reach" and v == 1:
            riichi[who] = True
        elif kind == "dora":
            dora.append(v)
```

使い方は次のとおりです。

```python

# {'対人': True, '赤なし': False, '喰いなし': False, '東南': True,
#  '三麻': False, '上卓': True, '速': False, '上級': True}

```

## 11. 解析が合っているかを確かめる

パーサは、**動いたように見えて間違っている**ことが多いので、確かめる仕組みが要ります。ここでは `replay` が、局を最初から再生しながら、次の整合性を `assert` で確認しています。

- 切った牌が、その時点で手牌にある
- チー・ポン・大明槓の牌が、直前の打牌に含まれ、鳴いた先が `(who + m & 3) % 4` と一致する
- 鳴いた牌・加槓の牌・暗槓の4枚が、手牌から取り除ける

3,000試合を再生した結果です。

```python
import glob, random
files = sorted(glob.glob(".../xml_logs/2023/*.xml"))
random.seed(0); files = random.sample(files, 3000)
n = 0
for p in files:
    meta, rounds = load(p)
    for rd in rounds:
        for s in replay(rd):
            n += 1
            assert len(s["hand"]) + 3 * len(s["melds"][s["who"]]) == 14
print(n)   # 1441017
```

- 3,000試合・30,127局・**1,441,017回の打牌**を再生して、エラーは0件
- 打牌の瞬間の手牌は、**常に14枚**(手牌 + 副露×3)で一致
- `owari` の持ち点の合計は、3,000試合すべてで100,000点

「全部通った」は、パーサが正しいことの証明ではありません。たとえば、牌の種類を取り違えても、手牌との整合性は崩れないことがあります。役ID表や赤5の数のような、**別の情報との突き合わせ**も併用しています(8章)。

## 12. AIの学習サンプルにする

`replay` が返す1件は、「誰かが牌を切る直前の状態」と「実際に切った牌(ラベル)」です。これが、打牌予測の1サンプルになります。

```python
meta, rounds = load(path)
sample = list(replay(rounds[1]))[40]
```

```
who     : 1
hand    : 4p 4p 5p 6p 7p 7p 8p 8p 9p 1s 3s 0s 6s 7s   (14枚。0s は赤5索)
drawn   : 8p       (直前のツモ牌)
label   : 8p       (実際に切った牌 = ツモ切り)
dora    : 8m       (ドラ表示牌)
melds   : なし
rivers  : 各自の河(牌IDとツモ切りの別)
riichi  : [True, True, False, True]   (座席0・1・3が立直中。座席1は本人)
```

`REACH step=1` は宣言牌を切る**直前**に出るので、リーチ宣言の打牌では、本人の `riichi` がすでに `True` です(上の例は、立直後のツモ切り)。宣言牌そのものを予測したいときは、`step=1` の前の状態を別に持ってください。

このサンプルを、そのまま特徴量にします。たとえば次の対応です。

| 入力 | 作り方 |
|---|---|
| 手牌 | 14枚を34種類のカウントに(`ID // 4`)。赤は別チャネル(ID 16・52・88) |
| 河 | `rivers[座席]` を、自分から見た相対席(4章)に並べ替える |
| 副露 | `melds[座席]` |
| ドラ | `dora` の表示牌から、ドラそのものを計算 |
| 立直 | `riichi` |
| ラベル | `label // 4`(34クラス)。または牌ID |

:::note warn
**情報漏洩に気をつけてください。** XMLには、次のような「その時点では分からない情報」が入っています。入力に入れると、実戦では使えないAIになります。

- 他家の手牌(`INIT` の `hai0`〜`hai3`、`AGARI` の `hai`)
- 牌山の乱数(`SHUFFLE`)
- 未来のドラ・裏ドラ(`doraHaiUra`)

`replay` は、その時点までのイベントしか使わないので、この点では安全ですが、`rd["init"]` を自分で別に読むときは注意してください。
:::

## 限界

- 動作確認は、天鳳2023年の4人打ち・赤あり・鳳凰卓(東風・東南)だけです。他の年、他の卓、三麻、赤なしでは確かめていません
- 役ID表は、確かめられたものだけを載せました。役満など、頻度が低いものは、突き合わせをしていません
- `SHUFFLE` からの牌山の再現は扱っていません
- `replay` は、**喰い替えなどの禁止手を検査しません**。牌譜は実際の対局なので、反則手はありません
- ここに書いた仕様は、公式の仕様書ではなく、先行記事と、実ログとの突き合わせによる理解です。変更や例外があるかもしれません

## まとめ

- mjlogは、gzipで圧縮した、入れ子のないタグの列。`INIT` で局が区切られる
- 牌は0〜135のID。**種類は `ID // 4`、赤5は 16・52・88**
- 座席は起家基準。親、自風、相対位置は自分で計算する
- 副露の `m` は、下位ビットで種類、下位2ビットで鳴いた先が決まる
- ツモ切りの印はなく、直前のツモ牌と同じかで判定する
- ダブロン、回線落ち、流局の手牌には、専用の扱いが要る
- **再生して整合性を確かめる**と、パーサの間違いにすぐ気づける。3,000試合・144万打牌で、エラー0件
