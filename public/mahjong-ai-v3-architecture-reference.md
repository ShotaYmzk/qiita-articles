## はじめに

私が作った麻雀AI(v3)のモデル構造を、**実装レベルで**まとめたリファレンスです。入力テンソルの形、各チャネルの意味、トークンの作り方、パラメータの内訳まで書きます。

Transformer や Attention の考え方から知りたい方は、先に[解説編(麻雀しか知らなくても分かる v3 の中身)](https://qiita.com/ShotaYmzk/items/fc01e52811fd78ee4dd5)を読んでください。全体の結果は[網羅編](https://qiita.com/ShotaYmzk/items/521b6950cecc1606f625)にあります。

:::note info
数字はすべて、強いモデル(天鳳2009〜2024年の16年分で学習、人間の打牌との一致率 77.81%)の実際の設定と重みから取りました。パラメータ数は、保存済みのチェックポイントの重みを数えた値です。
:::

## 1. 全体像

![v3の全体像](https://raw.githubusercontent.com/ShotaYmzk/mahjong-ai-qiita-images/main/v3_flow.png)

1サンプル = 1回の打牌判断です。入力は、次の3種類のトークンを1本に並べた系列です。

| トークン | 個数 | 中身 |
|---|---:|---|
| 局情報 | 1 | 局の状況を表す41個の数値 |
| 牌 | 37 | 打牌の候補(34種 + 赤5の3種)ごとに、27チャネルの特徴 |
| イベント | 最大128 | 局の最初から判断までの出来事(他家のツモは除く) |

系列の長さは固定ではなく、局面ごとに変わります。128は設計上の上限(位置の埋め込みの数)で、実際の局面では、これよりずっと短くなります。

実データで数えた、イベント数の分布です(天鳳、強制ツモ切りを含む全判断。2018〜2024年のvalidから10分の1 = 710万局面)。

| | イベント数 | 全体のトークン数(1 + 37 + イベント数) |
|---|---:|---:|
| 平均 | 35.6 | 73.6 |
| 中央値 | 33 | 71 |
| 99パーセンタイル | 90 | 128 |
| 観測した最大(この抽出で) | 110 | 148 |

学習データ(2009〜2024年の50分の1 = 1,660万局面)でも、平均35.6、中央値33、観測した最大112で、ほぼ同じ分布でした。イベントが何個あるかは、巡目と鳴きの数で決まります。

全データ(2009〜2024年、全局・全視点の9,305万件)を数えると、**打牌の時点でモデルに入るイベント数の最大は114**(全体で最大152トークン)で、128を超える局は1件もありませんでした。104を超えるのは、全体の0.014%(1.26万件)です。

バッチで計算するときは、同じバッチの中の最長に、他の局面を空き(padding)で揃えます。空きは Attention から隠します。バッチの最長は、評価時に約95〜112(平均約100)だったので、**バッチ全体のトークン数は約133〜150(典型的には約138)** になります。「1局面のトークン数」は、上の表の約74(平均)です。

## 2. 入力テンソルの形

バッチサイズを B、イベント数の最大を L(128)とします。

| 名前 | 形 | 型 | 内容 |
|---|---|---|---|
| `tile_feat` | (B, 37, 27) | uint8 | 牌トークンの特徴。学習時にチャネルごとの値で割る |
| `round_feat` | (B, 41) | float | 局情報 |
| `ev` | (B, L, 5) | int | イベント。5列は 種別・牌・行為者・フラグ・巡目 |
| `ev_pad` | (B, L) | bool | True の位置は空き |
| `legal` | (B, 37) | bool | 切れる牌 |
| `y` | (B,) | int | 正解(人間が切った牌、0〜36) |

牌のクラスは37個です。0〜33が牌の種類(萬子1〜9、筒子1〜9、索子1〜9、字牌7)で、34〜36が赤5(萬・筒・索)です。

次の図は、天鳳2024年の実際の1局面(他家リーチあり)を、入力の形にしたものです。上から、手牌、牌トークン37個×特徴チャネル、イベント系列(50トークン)、局情報です。

![入力1サンプル](https://raw.githubusercontent.com/ShotaYmzk/mahjong-ai-qiita-images/main/v3_input_example.png)

この局面では、1 + 37 + 50 = 88トークンの系列になります。

## 3. 牌トークン: 27チャネルの中身

牌トークンの特徴は、27チャネルです。値は uint8 で保存して、学習時に右端の値で割ります。

| チャネル | 名前 | 割る値 | 意味 |
|---|---|---:|---|
| 0 | 手牌 | 4 | 手牌にある枚数 |
| 1 | 自分の副露 | 4 | 自分の副露に含まれる枚数 |
| 2 | ドラ値 | 4 | この牌1枚のドラ値(表ドラの枚数 + 赤なら1) |
| 3 | 見えている枚数 | 4 | 4人の河 + 全員の副露 + ドラ表示牌(自分の手牌は含まない) |
| 4 | 残り枚数 | 4 | 4 − 見えている枚数 − 自分の手牌 |
| 5〜9 | 下家 | 4,4,1,1,4 | 河の枚数・手出しの枚数・現物か・リーチ宣言牌か・副露の枚数 |
| 10〜14 | 対面 | 同上 | 同上 |
| 15〜19 | 上家 | 同上 | 同上 |
| 20, 21 | 牌効率 | 8, 40 | 切った後のシャンテン数・受け入れ枚数 |
| 22〜26 | 安全度 | 2,2,2,1,1 | 他家3人のスジ度・ノーチャンス・ワンチャンス |

現物は、その人の河にある牌と、その人のリーチ成立後に誰かが切って通った牌です。

### 20〜26は使っていません

強いモデルでは、牌効率(20, 21)と安全度(22〜26)のチャネルを、**値を0にして使っていません**。入力の次元は変えずに、値を0にして、末尾に「このグループはマスク中」のフラグ(2個)を足す作りです。そのため、牌トークンの入力は 27 + 2 = 29次元です。

派生特徴を入れても入れなくても、一致率の差は0.1ポイント未満でした(seed 1本の比較)。

## 4. 局情報トークン: 41個の数値

| グループ | 個数 | 内容 |
|---|---:|---|
| 場風 | 3 | 東・南・西(北場は天鳳に無いので除外) |
| 自風 | 4 | 東南西北 |
| 親の位置 | 4 | 自分・下家・対面・上家 |
| 局の進み具合 | 5 | 何局目・本場・供託・巡目・山の残り枚数(正規化) |
| ゲームの種類 | 5 | 東風・半荘・延長・南場・オーラス |
| 点数 | 4 | 自分の点数、他家3人との点差 |
| 順位 | 4 | 自分の順位(one-hot) |
| 他家のリーチ | 3 | 下家・対面・上家がリーチ中か |
| リーチの巡目 | 3 | その人が何巡目にリーチしたか |
| 他家の副露数 | 3 | 下家・対面・上家 |
| 自分 | 3 | リーチ中か、副露数、ドラ表示牌の枚数 |

これを `Linear(41→256)` で1個のトークンにします。

## 5. イベントトークン

局の最初から判断までの出来事を、時系列に並べます。1つのイベントは、5つの整数です。

| 列 | 内容 | 取りうる値 |
|---|---|---|
| 種別 | 何が起きたか | 空き, ドラ表示, ツモ, 打牌, チー, ポン, 大明槓, 加槓, 暗槓, リーチ(10種) |
| 牌 | どの牌か | 0〜36 の牌クラス、37 = 牌なし(伏せ牌) |
| 行為者 | 誰が | 自分・下家・対面・上家、なし(ドラなど)、空き |
| フラグ | 打牌の補足 | ツモ切り、リーチ宣言牌、リーチ後の打牌、鳴かれた牌(4ビット) |
| 巡目 | その人が何回目の打牌か | 0〜31 |

入れているのは、**自分のツモ**だけで、他家のツモは入れていません。牌が伏せられていて分からず、打牌の「ツモ切り」フラグで、情報は足りるためです。

「鳴かれた牌」のフラグは、鳴きが打牌の直後に起きるので、後の判断の時点では既知の情報です。判断の時点より後のイベントは、入りません(テストで確認しています)。

![同じ局面を、イベント系列と牌ごとの個数で見る](https://raw.githubusercontent.com/ShotaYmzk/mahjong-ai-qiita-images/main/v3_timing_and_river.png)

図は、同じ局面を「順序つきの履歴(イベント系列)」と「牌ごとの個数(牌トークン)」の2通りで見たものです。牌トークンの河のチャネルは、人ごとの河を牌ごとに数えただけで、順序は消えます。「いつ切られたか」「直近の牌」「リーチ後か」といった順序の情報は、イベント系列だけが持っています。

## 6. トークンを256次元にする

3種類のトークンは、それぞれ次のように256次元にします。

| トークン | 作り方 |
|---|---|
| 局情報 | `Linear(41→256)` + 種類の印(局) |
| 牌 | `Linear(29→256)` + 牌の種類の埋め込み(34種) + 赤かどうかの埋め込み(2種) + 種類の印(牌) |
| イベント | 6つの埋め込みの和(下記) + 種類の印(イベント) |

イベント1個は、次の6つの合計です。

| 部品 | 形 | パラメータ |
|---|---|---:|
| 種別の埋め込み | 10 × 256 | 2,560 |
| 牌の埋め込み | 38 × 256 | 9,728 |
| 行為者の埋め込み | 6 × 256 | 1,536 |
| 巡目の埋め込み | 32 × 256 | 8,192 |
| フラグ(4ビット)の線形変換 | 4 → 256 | 1,280 |
| 位置の埋め込み(局の先頭から、学習される絶対位置) | 128 × 256 | 32,768 |

![イベント1個の作り方](https://raw.githubusercontent.com/ShotaYmzk/mahjong-ai-qiita-images/main/token_sum.png)

イベントの合計には LayerNorm をかけます。

牌トークンの「牌の種類の埋め込み」は、赤5と普通の5で**同じ種類(5)の埋め込みを共有**します。違いは、「赤かどうか」の埋め込みだけです。

3種類を並べたあと、全体に LayerNorm と dropout(学習時 0.1)をかけます。

```python
r = round_proj(round_feat).unsqueeze(1) + type_emb[ROUND]                  # (B, 1, 256)
t = tile_proj(tile_x) + kind_emb(class_kind) + aka_emb(class_aka) + type_emb[TILE]   # (B, 37, 256)
e = event_emb(ev) + type_emb[EVENT]                                         # (B, L, 256)
x = drop(in_norm(torch.cat([r, t, e], dim=1)))                              # (B, 1+37+L, 256)
pad = torch.cat([zeros(B, 1 + 37), ev_pad], dim=1)                          # 局と牌は空きにならない
```

## 7. Transformer 本体

6層で、1層の作りは次のとおりです。

![Transformerの1層](https://raw.githubusercontent.com/ShotaYmzk/mahjong-ai-qiita-images/main/v3_encoder_layer_pre_norm.png)

| 項目 | 値 |
|---|---|
| 層数 | 6 |
| 幅(d_model) | 256 |
| ヘッド数 | 8(1ヘッドあたり32次元) |
| FFN の幅 | 1024 |
| 活性化関数 | GELU |
| 正規化 | pre-norm(各ブロックの前に LayerNorm)、最後にも LayerNorm |
| マスク | 空き(padding)だけ。**先読みを防ぐマスクは使わない** |
| dropout | 学習時 0.1 |

マスクについて補足します。文章を生成するAIは、「未来の単語を見ない」ためのマスクを使います。v3 は、判断の時点までの情報しか入力に入れていないので、全トークンが全トークンを見てよい作りです。

```python
class CustomEncoderLayer(nn.Module):
    def forward(self, src, src_key_padding_mask=None, need_weights=False):
        x = self.norm1(src)
        attn_out, w = self.self_attn(x, x, x, key_padding_mask=src_key_padding_mask,
                                     need_weights=need_weights, average_attn_weights=False)
        src = src + attn_out
        src = src + self.ffn(self.norm2(src))
        return src, w
```

## 8. 出力

```python
h = final_norm(x)                         # (B, 1+37+L, 256)
tile_h = h[:, 1:38]                       # 牌トークン37個だけ取り出す
logits = score_head(tile_h).squeeze(-1)   # Linear(256→1)、(B, 37)
logits = logits.masked_fill(~legal, -inf) # 切れない牌を除く
```

「牌ごとに、同じ重みで1つスコアを出す」作りです。37個の出力は、牌トークンの並び(クラス0〜36)と同じ順です。学習では、この37個を softmax にして、正解の牌の確率を上げます(交差エントロピー)。

## 9. パラメータの内訳

保存済みのチェックポイント(`model_best.pt`)の重みを数えた値です。

| 部分 | パラメータ数 | 割合 |
|---|---:|---:|
| Transformer 6層 | 4,738,560 | 98.2% |
| 入力側(局情報・牌・イベントの変換) | 85,504 | 1.8% |
| 最後の LayerNorm + 出力(256→1) | 769 | 0.02% |
| **合計** | **4,824,833** | |

1層あたり 789,760 です。

| 1層の部品 | パラメータ数 |
|---|---:|
| Attention(Q・K・V の変換 197,376 + 出力の変換 65,792) | 263,168 |
| FFN(256→1024 と 1024→256) | 525,568 |
| LayerNorm 2個 | 1,024 |

入力側の内訳です。

| 部品 | パラメータ数 |
|---|---:|
| 局情報の変換(41→256) | 10,752 |
| 牌の特徴の変換(29→256) | 7,680 |
| 牌の種類の埋め込み(34種) | 8,704 |
| 赤かどうかの埋め込み | 512 |
| イベントの埋め込み(上の6部品 + LayerNorm) | 56,576 |
| 種類の印(局・牌・イベント) | 768 |
| 入力の LayerNorm | 512 |

パラメータの大部分が Transformer の層に入っています。入力の作りに使う部分は、全体の2%以下です。

## 10. 学習の設定

| 項目 | 値 |
|---|---|
| データ | 天鳳2009〜2024年(16年分) |
| 評価 | 2018〜2024年の validation。強制ツモ切りを除いた約670万局面 |
| バッチサイズ | 2,048(512 ずつ4回に分けて計算) |
| エポック | 3(合計 1,217,811 step) |
| 最適化 | AdamW、学習率 3e-4、weight decay 0.01 |
| 学習率の計画 | 2,000 step のウォームアップ、最後は 1e-6 まで減衰 |
| 勾配のクリップ | 1.0 |
| dropout | 0.1 |
| 評価の間隔 | 5,000 step ごと |
| 環境 | RTX 4080 SUPER 1枚、約7.3日 |

結果は、validation で Top-1 77.81%、Top-3 97.65% でした。

## 11. 打牌以外の判断モデル(同じ骨格の拡張)

リーチ・鳴き・カンの判断用に、同じ骨格に**行動トークン**を足したモデルも作りました。

- 系列 = 局情報 1 + 牌 37 + 行動 8 + イベント L
- 行動は8種類: パス、チー(下・中・上)、ポン、大明槓、リーチ、カン
- 各行動トークンの最終的な表現から、行動ごとにスコアを出す(牌トークンと同じ形)
- 局情報トークンに「どの判断か」の埋め込みを足す。鳴く対象の牌のトークンには、印を足す
- 重みは、打牌モデルの重みから初期化できる

打牌モデルと同じ骨格なので、「牌ごとにスコアを出す」部分を「行動ごとにスコアを出す」に変えるだけです。このモデルは、まだ対局エンジンには組んでいません。

## 12. 設計で気をつけたこと

- **情報の漏れを防ぐ**: 判断より後のイベントが入らないこと、他家のツモを入れないことを、テストで確かめています
- **牌トークン = 出力の候補**: 牌ごとの特徴をその牌のトークンに乗せ、同じトークンからスコアを出すので、合法手のマスクがそのまま使えます
- **赤5を別の牌として数える**: 37クラスで、赤5の3種類を別に持ちます。種類の埋め込みは普通の5と共有します
- **派生特徴は入れない**: 牌効率や安全度のチャネルは、マスクできる形で用意していますが、強いモデルでは使っていません

## 限界

- 一致率は、人間の打牌との一致です。実戦での強さは測っていません
- 1つのモデル(1つのシード)の設定です。層数やヘッド数を変えた比較は、この記事の範囲に入れていません
- パラメータの数え方は、チェックポイントに保存された重みの数です(学習に使わない部品は含みません)

## まとめ

- v3 は、局情報1・牌37・イベント最大128を、256次元のトークンにして並べ、6層の Transformer(pre-norm、8ヘッド、FFN 1024)に通します
- 牌トークンの最終的な表現から、牌ごとにスコアを1つ出し、切れない牌を除いて確率にします
- パラメータは合計 4,824,833。98%が Transformer の6層です
- 入力は、牌の枚数・河・現物などの生に近い情報だけで、牌効率や安全度の派生特徴は使っていません
